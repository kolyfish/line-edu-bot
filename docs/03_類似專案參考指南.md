# 類似專案參考指南：做下一個 LINE × AI Bot 時抄哪裡

> 講義結語：「把 ai_teacher.py 換成其他用途的邏輯，就能做出客服 Bot、圖書館助理 Bot、班級公告 Bot。」
> 這份文件告訴你**哪些可以直接搬、哪些要改、哪些坑不用再踩一次**。

---

## 一、可直接複製的骨架

| 檔案 | 動作 | 說明 |
|------|------|------|
| `app.py` | **直接複製**，只改 import 名稱 | 驗簽、群組過濾、指令分派、長訊息分段都是通用的 |
| `ai_teacher.py` | 複製後**改名**（如 `ai_support.py`），改內容 | 人設與業務邏輯都在這 |
| `requirements.txt` | 直接複製 | 五個套件夠用 |
| `Procfile` | 直接複製 | `web: gunicorn -w 1 app:app` |
| `.gitignore` | 直接複製 | 已含 `.env`、`venv/`、`._*`、`.DS_Store` |
| `.env` | 複製結構，**換新的三把鑰匙** | 每個 Channel 的 token/secret 都不同 |
| `DEV_JOURNAL.md` | 複製架構，清空內容 | 全域規則要求 |

### 新專案起手式
```bash
cp -R "/Volumes/SSD 1T/line-edu-bot" "/Volumes/SSD 1T/line-新專案" && cd "/Volumes/SSD 1T/line-新專案" && rm -rf venv .git __pycache__ && python3 -m venv --copies venv && ./venv/bin/pip install -r requirements.txt && dot_clean -m .
```

## 二、換用途時要改的地方（只在 AI 邏輯那支）

`ai_teacher.py` 裡只有這幾個東西跟「教學」綁定：

| 變數 / 函式 | 教育 Bot | 換成客服 Bot 的例子 |
|-------------|---------|---------------------|
| `SYSTEM_PROMPT` | 高中教師、引導不給答案 | 客服人員、直接給答案、不懂就轉真人 |
| `HELP_MESSAGE` | 可問的科目 | 可查的服務項目 |
| `MAX_HISTORY_MESSAGES` | 20（引導需多輪） | 10（客服多為單題） |
| `MODEL` | Sonnet（解釋品質） | Haiku（量大、問題簡單、省錢） |
| `max_tokens` | 1500 | 500（客服回答短） |

`app.py` 可能要改的：

| 項目 | 何時改 |
|------|-------|
| `CLEAR_COMMANDS` / `HELP_COMMANDS` | 想加新指令（如 `/數學` 切換模式） |
| `ASK_PREFIXES` | 群組觸發詞不想用「問：」 |
| `handle_message` 的分派 `if/elif` | 新增指令或圖片處理 |

### System Prompt 四段式模板
```
你是一位 ____（個性形容詞）的 ____（角色），專門協助 ____（對象）____（任務）。

【職責範疇】
可以處理：____
不處理：____。遇到時 ____（怎麼婉拒、轉介給誰）。

【回答風格】
用繁體中文，____（語氣）。條列用「1. 2. 3.」或「・」。訊息會顯示在 LINE，不要使用 **、#、表格等 Markdown 符號。每次回覆控制在 ___ 字內。

【行為原則】
1. ____
2. ____
3. ____（記得寫出口條件 / 例外情況）
```
- 目標 200–400 字
- 第四段是每種 Bot 的靈魂：教育 Bot =「引導不給答案」、客服 Bot =「不確定就轉真人，不要編造」、公告 Bot =「只根據提供的公告內容回答」

## 三、不同 Bot 類型的設計差異

| | 教育 Bot（本專案） | 客服 Bot | 圖書館助理 | 班級公告 Bot |
|--|---|---|---|---|
| 需要記憶 | ✅ 多輪引導 | △ 少量 | ✗ | ✗ |
| 需要外部資料 | ✗ | ✅ FAQ / 訂單 | ✅ 館藏查詢 | ✅ 公告內容 |
| 群組模式 | 學生提問 | 通常不用 | 通常不用 | ✅ 主要場景 |
| 主動推播 | ✗ | △ | 還書提醒 | ✅ `push_message` |
| 推薦模型 | Sonnet | Haiku | Haiku | Haiku |

**需要外部資料時**：最簡單是把資料塞進 System Prompt（< 幾千字）；資料多了再考慮 Claude 的 tool use 讓它自己查。

## 四、踩過的坑清單（下個專案直接避開）

### 環境
| 坑 | 解法 |
|----|------|
| 外接 SSD 是 exFAT，venv 壞掉 | `python3 -m venv --copies venv` |
| exFAT 讓 venv 從 300MB 膨脹到 5GB | 256KB cluster + `._` 影子檔；`dot_clean -m` 清 |
| `._app.py` 這類檔案被 git 推上去 | `.gitignore` 加 `._*` |
| `ngrok http 5000` 回 403 | macOS AirPlay 佔 5000，改 5001 |

### LINE 平台
| 坑 | 解法 |
|----|------|
| 每則訊息先跳罐頭回覆 | OA Manager → 回應設定 → 自動回應**關** |
| 找不到 Channel secret | 要點進 Channel，不是 Provider 設定頁 |
| 群組 @Bot 不觸發 | 用 `mention.is_self`，不要比對顯示名稱字串 |
| 「問:」不觸發 | 手機輸入法打全形「問：」，兩種都要收 |
| 回覆出現 `**粗體**` 原字 | LINE 不吃 Markdown，System Prompt 要明講 |
| 長回覆被拒 | 單則 5000 字上限、一次最多 5 則 → 切 4000 |
| reply token 失效 | 只能用一次、約 1 分鐘過期 → 出錯也要回一句，不要 raise |

### Claude API
| 坑 | 解法 |
|----|------|
| 截斷歷史後 API 400 | 送出前確認第一則是 `user` |
| 失敗後下次連續兩則 user | 失敗時 `history.pop()` |
| 錯誤細節露給使用者 | log 記錯誤，使用者只看道歉訊息 |
| `Anthropic()` 讀不到 key | `load_dotenv()` 必須在 import AI 模組**之前** |

### 部署
| 坑 | 解法 |
|----|------|
| 本地正常、Render 不回 | `.env` 不會上傳，Render Environment 要另外設 |
| Bot 間歇性失憶 | 記憶在記憶體 → `gunicorn -w 1`；要持久就上 Redis |
| Verify 逾時 | Render 免費層休眠，先開首頁喚醒 |

## 五、上線前 Checklist

- [ ] `.env` 三把鑰匙填好，**不在** git 裡（`git status` 確認）
- [ ] OA Manager：Webhook 開、自動回應關

- [ ] 本地 `python app.py` + `ngrok http 5001` → Verify 綠燈 → 手機實測一則
- [ ] 推 GitHub 前 `dot_clean -m .`，確認沒有 `._*` 檔
- [ ] Render：Start Command `gunicorn -w 1 app:app`、三個環境變數、首頁回 `ok`
- [ ] Webhook URL 換成 `https://xxx.onrender.com/callback` → Verify
- [ ] 測：個人提問、清除、幫助、群組 @、群組閒聊不回

## 六、架構升級路線（量變大時）

```
現在：記憶體 dict + 單 worker + 同步呼叫 Claude
  ↓ 學生 > 幾十人 / 常重啟
Redis 存記憶 → 可開多 worker
  ↓ Claude 回應常超過 10 秒
收到 webhook 先回 200 → 背景處理 → push_message（reply token 會過期）
  ↓ 要給老師看數據
SQLite / Postgres 記錄每次提問（科目、時間），做儀表板
```
