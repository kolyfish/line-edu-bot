# LINE 教育 Bot 專案教學：從零到上線

> 依據 Claude Code 聖經 CH24，並補上講義沒寫、實作時踩到的坑（標 ⚠️）

---

## 0. 全貌：訊息怎麼跑一圈

```
學生在 LINE 傳訊息
   ↓ HTTPS POST
LINE 伺服器
   ↓ Webhook（帶 X-Line-Signature 簽章）
Render 上的 Flask  /callback        ← app.py
   ↓ 驗簽 → 群組過濾 → 指令分派
ai_teacher.get_ai_response()        ← ai_teacher.py
   ↓ System Prompt + 該學生最近 20 則歷史
Claude API
   ↓
reply_message 回 LINE（超過 4000 字自動分段）
```

**核心觀念**：LINE 不會「呼叫你的程式」，而是把訊息 POST 到你給它的網址（Webhook URL）。所以你的程式必須跑在**公開網址**上（Render 或 ngrok）。

## 1. LINE 端設定

### 1-1 建立 Channel（developers.line.biz）
1. 登入 → 建 Provider（本專案：`create_taiwan`）
2. 建 **Messaging API Channel**，名稱 `AI 教學助理`、類別「教育」

### 1-2 取得兩把鑰匙
| 名稱 | 位置 | 用途 |
|------|------|------|
| Channel secret | Channel → **Basic settings** | 驗證請求真的是 LINE 發的 |
| Channel access token | Channel → **Messaging API** → 最底 → Issue | 讓你的程式能回訊息 |

⚠️ Provider settings 頁看不到這兩個，要**點進 Channel**。

### 1-3 OA Manager 設定（manager.line.biz）
右上 **設定 → 回應設定**：
- Webhook：**開**
- 自動回應訊息：**關** ⚠️ 講義沒寫，沒關的話每則訊息會先跳 LINE 罐頭回覆
- 聊天：維持關閉（開了會變真人客服模式）

### 1-4 群組功能（選用）
Messaging API 頁 → **Allow bot to join group chats** → ON

## 2. 本地環境

```bash
cd "/Volumes/SSD 1T/line-edu-bot"
```

```bash
python3 -m venv --copies venv
```

```bash
source venv/bin/activate && pip install -r requirements.txt
```

⚠️ **外接 SSD（exFAT）專用**：
- 一般 `python3 -m venv` 會用 symlink，exFAT 不支援 → 必須加 `--copies`
- macOS 會在 exFAT 上生一堆 `._xxx` 影子檔，造成 pip 警告、git 誤加 → 定期清：
  ```bash
  dot_clean -m "/Volumes/SSD 1T/line-edu-bot"
  ```
- 放在 APFS 磁碟（Mac 內建硬碟）不會有這些問題

### `.env`（絕不進 git）

## 3. 程式碼導讀

### 3-1 分工原則
| 檔案 | 只管 | 換成別的 Bot 時 |
|------|------|-----------------|
| `app.py` | LINE 平台：驗簽、群組過濾、指令、分段回覆 | 幾乎不用改 |
| `ai_teacher.py` | AI 邏輯：人設、記憶、Claude 呼叫 | **主要改這支** |

### 3-2 `app.py` 重點
**驗簽**：`handler.handle(body, signature)` 用 Channel secret 算 HMAC，不符就 400。這是防止有人偽造請求白嫖你的 Claude 額度。

**群組過濾** `extract_group_question()`：
```python
self_mention = next((m for m in mentionees if getattr(m, "is_self", False)), None)
```
⚠️ 講義用 `"@AI教學助理" in text` 字串比對，但 Bot 顯示名稱是「AI 教學助理」（**有空格**），永遠比對不到。LINE 的 mention 資料自帶 `is_self`，直接問「是不是 @ 我」最準。

**長訊息分段** `split_reply()`：LINE 單則上限 5000 字、一次最多回 5 則 → 切 4000 留緩衝。

**`load_dotenv()` 要放在 `import ai_teacher` 之前**：ai_teacher 一被 import 就建立 `Anthropic()`，那時要讀得到 API key。

### 3-3 `ai_teacher.py` 重點
**System Prompt 四段式**（200–400 字最佳，本專案 341 字）：
1. 角色定位：你是誰、服務誰
2. 職責範疇：能處理 / 不處理什麼
3. 回答風格：語言、語氣、格式（⚠️ LINE 不吃 Markdown，要明講別用 `**` `#`）
4. 引導原則：不直接給答案 + **出口條件**（試兩次仍卡住才示範），沒出口學生會被無限追問

**對話記憶**：
```python
user_conversations = defaultdict(lambda: deque(maxlen=20))
```
- 以 `user_id` 為 key → 每個學生獨立，不會互相洩漏
- `deque(maxlen=20)` 自動丟最舊的，取代講義的 `list[-20:]`
- ⚠️ 講義版本兩個 bug，本專案已修：
  1. 切到 20 則後可能以 `assistant` 開頭 → Claude API 回 400 → 送出前檢查第一則
  2. Claude 失敗時提問留在歷史 → 下次出現連續兩則 user → 失敗就 `pop()` 掉

**錯誤處理**：失敗時回「抱歉，我現在有點忙」而不是 raise，因為 reply token 只能用一次、約 1 分鐘過期；也不把 `str(e)` 回給學生（講義做法會洩漏錯誤細節）。

## 4. 本地測試（ngrok）

```bash
source venv/bin/activate && python app.py
```

另開一個 terminal：
```bash
ngrok http 5001
```

⚠️ **用 5001 不是 5000**：macOS 的 AirPlay 接收器（ControlCenter）佔用 5000 port，講義的 `ngrok http 5000` 會打到 AirPlay 回 403。

把 ngrok 給的 `https://xxxx.ngrok-free.app/callback` 填到 LINE Developers → Messaging API → Webhook URL → 開 **Use webhook** → 按 **Verify**。

## 5. 部署到 Render

1. 推上 GitHub（確認 `.env`、`venv/`、`._*` 都在 `.gitignore`）
2. render.com → New → **Web Service** → 選 repo → Free 方案
3. Start Command：`gunicorn -w 1 app:app`（或直接讀 `Procfile`）
4. **Environment** 填三個環境變數 ⚠️ `.env` 不會上傳，這步最常漏
5. 拿到 `https://xxx.onrender.com` → 先開首頁看到 `ok`（喚醒）
6. LINE Webhook URL 改成 `https://xxx.onrender.com/callback` → Verify

⚠️ **為什麼 `-w 1`**：對話記憶存在 process 記憶體，多個 worker 各自一份，學生下一則訊息可能落到另一個 worker 就「失憶」。

## 6. 排錯對照表

| 現象 | 原因 | 解法 |
|------|------|------|
| Verify 失敗（逾時） | Render 休眠中 | 先開首頁喚醒再 Verify |
| Verify 失敗（404） | URL 少了 `/callback` | 補上 |
| `Invalid signature` / 400 | Channel secret 錯 | 重新複製，更新 Render 環境變數 |
| 有收到但不回 | Render 沒設環境變數 | Render → Environment |
| 每則先跳罐頭訊息 | OA Manager 自動回應沒關 | 回應設定 → 關 |
| 群組 @ 了沒反應 | 沒開 Allow join group / 舊版字串比對 | 開設定；本專案已用 `is_self` |
| 本地 ngrok 403 | 5000 被 AirPlay 佔 | 改 5001 |
| pip 跳 `Ignoring invalid distribution -xxx` | exFAT `._` 影子檔 | `dot_clean -m` |
| 學生說 Bot 失憶 | 重啟 / 多 worker / 超過 20 則 | `-w 1`；要持久就上 Redis |

**最快除錯**：Render Dashboard → 服務 → **Logs**，看 `簽章驗證失敗`、`Claude 呼叫失敗` 這兩種 log。

## 7. 延伸方向
| 方向 | 做法提示 |
|------|---------|
| 作業拍照辨識 | 加 `ImageMessageContent` handler → 用 MessagingApiBlob 下載圖 → base64 丟 Claude（image content block） |
| 對話持久化 | `user_conversations` 換成 Redis（`LPUSH` + `LTRIM 0 19`），順便解掉 `-w 1` 限制 |
| 學習分析儀表板 | 每次提問讓 Claude 順便輸出科目分類，存 SQLite，老師看統計 |
| 科目專精模式 | `/數學`、`/物理` 指令切換 per-user 的 System Prompt 附加段落 |

## 8. 金鑰防漏（推 GitHub 前必做）

| 防線 | 檔案 | 擋什麼 |
|------|------|-------|
| 1 | `.gitignore` | `.env`、`.env.*`、`*.pem`、`*.key` |
| 2 | `.githooks/pre-commit` | `git add -f .env`、任何檔案內容含 `.env` 真實值、gitleaks 規則命中 |
| 3 | `.githooks/pre-push` | 用 `--no-verify` 繞過 commit 的漏網之魚 |

clone 到新電腦後要重新啟用 hook：
```bash
git config core.hooksPath .githooks && brew install gitleaks
```

⚠️ 萬一金鑰真的推上去了：**先到 LINE Developers / Claude Console 撤銷並重發金鑰**，再處理 git 歷史。刪 commit 沒用，GitHub 和爬蟲可能已經抓走了。
